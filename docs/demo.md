# Демонстрация v2 за четыре минуты

Выполните `npm ci`, задайте приватный `DATA_DIR`, запустите `npm start`. После `npm run models:setup` нажмите «Подготовить поиск» и дождитесь готового E5. Для показа используйте только авторские демо-обращения.

1. В очереди откройте жалобу: исходный текст, извлечённые заявления, канонический пункт и условный черновик. Количество вложений не означает, что они просмотрены.
2. В базе знаний введите вопрос на другом языке. Покажите реальный режим E5/BM25 и объясните, что кандидат поиска ещё не разрешение цитировать правило.
3. Откройте платёж/взлом/угрозу: обязательная проверка человеком остаётся. Сохраните правку, перезапустите приложение и покажите сохранённые текст/feedback.
4. Пересоберите радар. Из темы создайте предложение инструкции; до одобрения оно не активно. Одобрите, найдите его отдельно от правил, затем отзовите и повторите поиск.
5. В лаборатории качества сначала покажите отсутствие меток и недоступные метрики. Разметьте именно демо-запись с заметкой о синтетике, запустите сравнение, покажите знаменатели и происхождение.
6. Импортируйте небольшой авторский JSONL, покажите progress и сохранение данных. Повторный разбор не стирает ручной ответ.
7. Откройте `docs/evaluation-v2.md`: 1000 реальных HTTP запросов, p95 45.20мс, exact-source holdout19/24 против3/24 lexical, пять промахов и три FAQ с дополнительным human. Это не real accuracy без gold.
8. Генератор покажите как эксперимент с default off и ограниченными формулировками. Свободный Qwen benchmark не прошёл качество; дообучение не выполнялось. Не называйте ноутбук обучения обученной моделью.

Проверки перед защитой: `npm test`, `npm run package:check`; модели и приватные данные устанавливаются отдельно. `make predict` по умолчанию v2, для прямого CLI нужны `--mode v2 --initialize`. Если ноутбук выключится, запустите приложение снова; задания можно возобновить. Для CLI-импорта в ту же очередь сначала остановите сервер.
