# Публичная демонстрация на Render

Это отдельный demo-режим рабочего интерфейса. Он использует только свежие авторские материалы из `data/hosting-demo/`: правила 9001+ явно помечены как **не официальные правила Grand Mobile**. Таксономия использует уже опубликованные 14 кодов категорий с новыми demo-подписями. Приватные handout, обращения, индексы и модели не загружаются в хостинг.

## Конфигурация

`render.yaml` описывает один Node.js 22 web service на free plan. Автоматический deploy выключен; платных дисков и баз данных нет. Build: `npm ci --no-audit --no-fund`; start: `node scripts/start-hosted.mjs`; health check: `/healthz`.

Launcher задаёт `HOST=0.0.0.0`, `ALLOW_REMOTE=1`, отдельный demo DATA_DIR и runtime. Генератор выключен, HTTP работает в fast-режиме. На старте нет model setup, E5 initialization, загрузки весов или обращения к внешнему LLM API. Поиск работает в явно обозначенном fallback; это не hosted-проверка семантической модели.

Origin берётся из `PUBLIC_ORIGIN` либо предоставленного Render `RENDER_EXTERNAL_URL` и должен точно иметь форму `https://service.onrender.com`, без завершающего slash, path, query и credentials. Сервер использует этот origin для ограниченного удалённого доступа. Для собственного домена задайте его точный HTTPS origin вручную.

## Вход

`SUPPORT_ADMIN_USER` по умолчанию `admin`. `SUPPORT_ADMIN_PASSWORD` обязателен: минимум 16 символов, рекомендуется автоматически сгенерированный случайный секрет. В Blueprint используется `generateValue: true`; получите значение в своём Render dashboard и храните его как пароль, не вставляйте в URL, README, логи или Git. Реализация доступа проверяется отдельно; launcher не подменяет её.

Запросы к интерфейсу/API требуют авторизацию. `/healthz` предназначен только для безопасной проверки жизнеспособности и не должен возвращать очередь, настройки или секреты. Работоспособность внешнего URL подтверждается после фактического deploy, а не наличием YAML.

## Порядок публикации

1. Root проверяет, что публичный commit содержит launcher, авторские demo-данные, server access guard и эту конфигурацию. Приватные материалы и веса отсутствуют.
2. В существующем аккаунте Render выберите этот публичный репозиторий и `render.yaml`, сохранив **free** plan. Не подключайте платные ресурсы. Deploy выполняется только по отдельному явному разрешению пользователя.
3. Проверьте env origin и сгенерированный пароль. Не меняйте локальные системные настройки и не используйте production handout как build input.
4. После запуска проверьте `/healthz`, отказ неавторизованного API, успешный вход, очередь, авторский `POST /triage`, сохранение ручной правки и local outbox. Нативная генерация должна оставаться выключенной.

## Ограничения free demo

Runtime хранится на временной файловой системе; redeploy или пересоздание сервиса может сбросить очередь, правки и feedback. Free service может засыпать и медленно отвечать на первый запрос. Это не постоянное рабочее хранилище и не перенос локального состояния пользователя. Платный persistent disk этим Blueprint не создаётся.

Ответы остаются локальными записями сервиса: отправки в игру нет. Не вводите реальные обращения, пароли, платёжные данные или другой приватный материал в публичный demo. Для реальных правил/семантического поиска используйте локальный режим из README с отдельно предоставленным DATA_DIR.

При остановке launcher передаёт SIGTERM/SIGINT своему server child и ждёт его фактического закрытия; после 10 секунд завершает только этого дочернего процесса. Статус фактического deploy и последующие проверки сохраняет root отдельно от подготовки.
